# worknav — 작업 길잡이 표지판 (VS Code)

작업하다 "내가 왜 이걸 하고 있었지"가 되는 걸 막는 한 줄입니다. VS Code 하단 상태 표시줄에 고정으로 뜹니다.

```
⟩ 논문 실험 파트 재현 › ablation S_… › seed 고정  d2  ⑂2
```

- 맨 왼쪽 — 원래 하려던 것(루트 목표)
- 맨 오른쪽 — 지금 실제로 붙잡고 있는 것
- `d2` — 두 단계 내려왔다
- `⑂2` — 나중에 할 것 2개를 담아뒀다

마우스를 올리면 전체 경로와 각 단계의 복귀지점이 나옵니다. 클릭하면 전체 트리가 열립니다.

## 왜 따로 있나

worknav 본체는 Claude Code 플러그인이고, 표지판은 Claude Code 터미널 상태줄에 뜹니다.
그런데 VS Code 확장의 사이드바 채팅 UI로 작업하면 그 줄이 보이지 않습니다 — 상태줄은
터미널 화면 전용 요소이고, 웹뷰에는 그릴 코드 자체가 없습니다.

이 확장은 그 표지판을 VS Code 상태 표시줄로 옮깁니다. 사이드바로 작업하든 파일을 보든
같은 자리에 계속 남습니다.

## 동작 방식

`<git 루트>/.claude/worknav/state.json` 을 **읽기만** 합니다. 1초마다 파일이 바뀌었는지만
확인하고, 바뀌었을 때만 다시 그립니다. Claude Code 와 직접 연결하지 않기 때문에 CLI 나
Claude Code 확장이 업데이트돼도 깨지지 않습니다.

상태 파일이 없거나 깨졌으면 **아무것도 띄우지 않습니다.** 틀린 표지판은 없는 표지판보다
나쁘기 때문에, 추측해서 그리지 않습니다.

## 설치

1. worknav 본체를 먼저 설치합니다 (Claude Code 플러그인 또는 `install.sh`)
2. 이 확장을 설치합니다

```bash
cd vscode-ext
npx @vscode/vsce package        # worknav-statusbar-0.1.0.vsix 생성
code --install-extension worknav-statusbar-0.1.0.vsix
```

`.claude/worknav/state.json` 이 생기는 순간부터 표지판이 뜹니다. 별도 설정은 필요 없습니다.

## 명령

| 명령 | 하는 일 |
| --- | --- |
| `worknav: 전체 트리 보기` | 지금까지의 가지 전부 (상태바 클릭과 같음) |
| `worknav: 보류함 보기` | 나중에 하기로 담아둔 것들 |
| `worknav: 상태 다시 읽기` | 즉시 갱신 |

작업 중에는 전체 트리를 자동으로 띄우지 않습니다. 형제 노드가 눈에 들어오면 도구가
가지치기를 다시 부추기기 때문입니다.

## 설정

| 키 | 기본값 | 설명 |
| --- | --- | --- |
| `worknav.enabled` | `true` | 표지판 표시 여부 |
| `worknav.statePath` | `""` | 상태 파일을 직접 지정 (비우면 git 루트에서 자동 탐색) |
| `worknav.maxWidth` | `52` | 한 줄의 최대 폭 (한글은 2칸) |
| `worknav.titleMax` | `12` | 노드 제목 하나의 최대 글자 수 |
| `worknav.alignment` | `left` | 상태 표시줄에서 붙는 쪽 |
| `worknav.pollIntervalMs` | `1000` | 변경 확인 주기 |
| `worknav.warnBackgroundFromDepth` | `3` | 이 깊이부터 배경을 경고색으로 (`0` 이면 사용 안 함) |

**줄이 잘려 보인다면** `worknav.maxWidth` 를 낮추세요. 다만 루트와 현재 위치는 어떤 값에서도
버리지 않기 때문에 30칸 언저리가 실제 하한입니다. 길을 잃는다는 건 정확히 출발지를
잊는다는 뜻이라서, 폭을 아끼려고 그 둘을 버리지는 않습니다.

## 표지판이 두 개가 되는 문제

터미널 상태줄(파이썬)과 이 확장(JS)은 서로 다른 코드로 같은 파일을 읽습니다. 둘이 다른
말을 하기 시작하면 둘 다 못 믿게 되므로, `test/cross_python.test.js` 가 같은 상태에서
두 렌더러의 출력이 문자 단위로 같은지 매번 확인합니다.

표시 규칙을 바꿀 때는 `src/render.py` 를 먼저 고치고 `src/render.js` 를 맞추세요.

## 개발

```bash
npm test        # 의존성 없음. node --test 만 씁니다
```

테스트는 실제 `wn.py` 를 돌려 만든 상태 파일로 확장을 구동합니다 (`test/e2e.test.js`).
합성 픽스처만 쓰면 CLI 가 실제로 쓰는 스키마와 어긋나도 통과하기 때문입니다.

## 요구사항

- VS Code 1.75 이상
- 표지판 표시 자체에는 외부 의존성이 없습니다 (Node 표준 라이브러리만 사용)
- 상태 파일을 만드는 worknav 본체는 Python 3.8+ 만 필요합니다. Windows / macOS / Linux
  전부 동작합니다 (파일 잠금은 플랫폼에 따라 `fcntl` 과 `msvcrt` 를 갈라 씁니다)

Windows 에서의 동시 쓰기(같은 프로젝트에 Claude Code 세션 두 개)는 코드 경로만 갖춰 두고
실제 환경에서 확인하지는 못했습니다. 세션 하나로 쓰는 한 문제되지 않습니다.
